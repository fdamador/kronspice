## What was added

- **`.model name D(...)`** parsing and validation (SPICE3 level-1
  parameters IS, N, RS, CJO, VJ, M, TT, BV, IBV, FC; EG, XTI, KF, AF, TNOM
  are accepted and range-checked but have no effect until temperature and
  noise models arrive). Element line `Dname anode cathode model [area]`.
  Builder: `Model(...)`, `Diode(...)`.
- **`device.Diode`** (SPICE3 level 1, equations ported from the published
  model, not from SPICE3 code):
  - forward, reverse and breakdown current; the breakdown voltage is
    adjusted so the current at BV equals IBV, as in SPICE3;
  - series resistance through an internal node;
  - depletion charge with the FC linear continuation, plus diffusion charge
    TT·id, integrated with the same trapezoidal / backward-Euler companion as
    capacitors, with truncation-error control;
  - `pnjlim` junction limiting, including in breakdown;
  - all external channels present (`TestAllChannelsPresent`); thermal port
    carries the dissipated power, stored junction energy ∫v dq is reported.
- **Newton–Raphson** (`analysis/newton.go`): SPICE3 convergence test (no
  limiting in the last iteration, every unknown within
  reltol·|x| + vntol or abstol, every device's own current check), ITL1 = 100
  for DC and ITL4 = 10 per time step. Circuits without nonlinear devices
  still take exactly one solve.
- **DC fallback chain:** plain Newton → gmin stepping (1e-2 S from every
  node to ground, reduced adaptively to 0) → source stepping (ramping all
  sources from 0, step halved on failure). Pseudo-transient continuation is
  not implemented yet.
- **Transient:** Newton at every step from the previous solution; a step
  that fails to converge in ITL4 iterations is retried at one eighth of the
  size (SPICE3 behaviour) and counts as a rejected step.
- **DC sweeps** start each point from the previous solution (continuation).
- **Options:** `RelTol`, `AbsTol`, `VnTol`, `Gmin`, `ITL1`, `ITL4`,
  `NoGminStepping`, `NoSourceStepping` (moved from `TranOptions` into
  `Options`, so they apply to every analysis).
- **Ledger:** storage is now the `StoragePower` part of each element's
  absorbed power (a diode both dissipates and stores). A residual below
  1e-21 W passes regardless of scale (`output.LedgerAbsFloor`), because when
  every power is itself round-off — a diode circuit with all sources at 0 V —
  the relative residual is meaningless.
- **Golden harness:** DC-sweep tables (`sweep,...` header), compared point
  by point with the DC tolerances; golden `Values` now include every
  element's current.

## How the references were made

ngspice is not installable here, so the five new golden files come from an
independent Python implementation of the same model equations
(`internal/golden/ref/diode_ref.py`, standard library only): DC points by
bisection to machine precision, transients by fourth-order Runge–Kutta at
1 ps / 10 ns steps. It shares no code with the Go solver. When ngspice is
available, `internal/golden/cmd/regen` should be extended to `.dc` and
`.tran` and the files regenerated, as CLAUDE.md asks.
